# Support

GitHub Issues is UIWitness's single public support and feedback path. GitHub Discussions is intentionally disabled so maintainers and users have one searchable queue and one response history.

Choose the issue form that matches your need:

- [Bug report](https://github.com/RujitRaval/uiwitness/issues/new?template=bug_report.yml) for reproducible incorrect behavior.
- [Customer pilot feedback](https://github.com/RujitRaval/uiwitness/issues/new?template=customer_pilot_feedback.yml) for structured feedback from a real evaluation or pilot.
- [Feature evidence](https://github.com/RujitRaval/uiwitness/issues/new?template=feature_evidence.yml) for an evidence-backed product request tied to an observed job or failure mode.

Before posting, remove credentials, customer records, private URLs, and identifying application data. Do not attach `.uiwitness/` or legacy `.statecraft/` evidence until you have reviewed every screenshot, URL, verdict, proposal, and diagnostic. A textual, sanitized reproduction is the safest starting point.

Suspected vulnerabilities, leaked credentials, and sensitive report exposure do not belong in Issues. Use [GitHub private vulnerability reporting](https://github.com/RujitRaval/uiwitness/security/advisories/new) as described in [SECURITY.md](SECURITY.md). Report Code of Conduct concerns through the private contact in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
