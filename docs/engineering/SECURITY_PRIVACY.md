# Security and Privacy

UIWitness may capture sensitive application screens.

- No telemetry in v0.1.
- No automatic upload of screenshots, reports, URLs, diagnostics, or source data.
- No external assets in generated reports.
- Do not persist authorization headers, cookies, tokens, or sensitive request bodies by default.
- Sanitize request diagnostics.
- Capture only failed-request URL, method, and error text; never inspect or retain request headers, response headers, cookies, or bodies. Remove URL credentials and fragments, replace every query value with `[REDACTED]`, redact authorization/cookie values and common token/secret assignments in free-form console and page-error text, pre-bound every value before sanitizing, and cap both diagnostic sizes and counts. Never attach an original unsanitized throwable as a public error cause.
- Config/scenario modules are trusted local code running with user privileges; importing a config can execute arbitrary local code. Default config lookup checks names only inside the selected project directory, returns canonical paths (including symbolic-link targets), and refuses ambiguous files instead of silently executing one. An explicit config path may point elsewhere.
- `uiwitness init` never offers a force mode. It rejects existing generated targets and symbolic-link directory boundaries, creates files exclusively, publishes the config last, and never deletes paths during failure recovery because a concurrently changed path may no longer be owned by that invocation.
- `uiwitness scan` executes trusted config and scenario modules locally, writes runner-owned PNG and schema-v1 JSON output plus report-owned HTML beneath the invocation directory's `.uiwitness/`, and prints report metadata rather than diagnostic payloads. Exact route validation completes before output creation.
- Optional authentication is one trusted local module executed once in a runner-owned setup context. It reads environment or secret-manager values directly and must return no data. UIWitness snapshots Playwright storage state without a path, validates local-storage origins and cookie domain/path/secure/partition scope, deep-copies the validated state into each fresh cell context, and holds no owned reference after run cleanup. The setup path must be a readable, single-link regular file beneath the canonical invocation workspace with no symbolic-link boundary. Exact application cookies are implicit; every parent, sibling, leading-dot, additional-domain, or partitioned cookie requires an explicit scope, and public suffixes are always refused. No UIWitness serializer, diagnostic, report, verdict, fingerprint, log, error cause, temporary path, or generated artifact receives cookie/local-storage/header/environment values or setup return values. Opaque failures expose only `AUTH_SETUP_INVALID`, `AUTH_SETUP_FAILED`, `AUTH_ORIGIN_NOT_ALLOWED`, or `AUTH_COOKIE_NOT_ALLOWED` plus the non-secret module path.
- Authentication setup and scenario modules remain fully trusted arbitrary code: they can read, print, transmit, or throw secrets themselves. UIWitness does not sandbox them and does not claim JavaScript heap erasure. `shared-readonly` is an operator promise that cells do not mutate shared server state. Stored auth files, multiple roles, per-cell login, and authenticated sharding are outside T9; fork pull requests stay secret-free, and authenticated CI runs only for an exact reviewed commit on a protected trusted branch/environment.
- `uiwitness guard` treats the canonical invocation directory as a strict workspace. Config, contract, every scenario, the default verdict, and any explicit `--json` copy must stay beneath it through regular non-symbolic-link boundaries. Guard validates these boundaries before browser launch, compares only its fresh complete in-memory report, keeps messages and raw diagnostic payloads out of contract findings, and supplies owner-private verdict bytes to the runner's generation transaction. Route fingerprints use redacted query values and omit userinfo and fragments. Explicit JSON output is no-clobber; existing parent directory permissions are preserved.
- Failed complete guards and failed initializations produce a canonical message-free source snapshot, immutable content-addressed proposal, and owner-private metadata overlay beneath `.uiwitness/` in the same committed generation as report/evidence and verdict output. Repeated identical runs may reuse byte-identical source/proposal files but never overwrite an existing valid overlay. Proposal inspection, annotation, and acceptance reject symbolic links, hard links, digest/filename mismatches, noncanonical bytes, stale contracts/configs, unknown changes, irrelevant metadata, and concurrent writers. Guard holds the contract-writer lock from its contract snapshot through runner publication; acceptance takes that lock and then the runner generation lock through marker revalidation, contract commit, and proposal consumption. Acceptance additionally requires the proposal source digest and exact source/proposal roles to resolve through the current digest-bound generation marker, regenerates the proposal, applies only named changes, safely publishes the contract, and consumes the proposal and overlay. These local files may still describe private route/state inventories, so they share the evidence tree's ignore and retention guidance.
- Known-failure exceptions expose their owner, reason, creation date, expiry date, exact expected/actual codes, and UTC lifecycle in local terminal output, the private verdict and HTML report, and bounded GitHub summaries/annotations. Do not put secrets, customer data, or raw diagnostic text in owner or reason fields. New annotations reject control and default-ignorable Unicode characters; schema-v1 contracts retain input compatibility, while terminal, HTML, and GitHub presentations render any legacy control or invisible character as an explicit code-point escape so ownership and renewal intent cannot be spoofed. Expired exact failures require a new explicit proposal annotation with an updated reason and current 1–30 day window; recovery removes the exception, changed eligible failure codes require a new expectation decision, ineligible failures must be repaired, and dates never renew automatically.
- `uiwitness check` accepts only one absolute credential-free HTTP(S) URL, strips the starting query and fragment before discovery, bounds attempts to 1–20 pages, and follows only same-origin HTML candidates. It runs page JavaScript and ordinary page requests, so use it only on sites you own or are authorized to test. The command snapshots the output root before browser work, persists through the same private `.uiwitness/` transaction, sanitizes terminal-controlled strings, prints no raw diagnostics, and hides unexpected runner/filesystem details behind exit code `2`. It never uploads evidence. Only explicit `--write-config` creates executable `.mts` project files: every supported config name, target, and directory boundary is checked before browser launch; files use exclusive creation; the scenario is written before the config; symbolic-link boundaries and overwrites are refused; and failure recovery never deletes paths.
- Project-file publication rejects symbolic-link boundaries observed during validation. It is pathname-based and, like `scan` and `open`, trusts the local project directory against hostile concurrent same-user replacement between validation and creation.
- Phase 5 HTML generation validates through the schema-v1 core parser, derives screenshot references only from validated artifact paths, HTML-escapes every report-controlled string, embeds no external asset, and sets a restrictive document Content Security Policy. Its constant filter/detail/copy script contains no report values and is authorized only by its exact SHA-256; external scripts remain blocked. Optional contract-first rendering validates the schema-v1 verdict, canonical finding order, digests, outcomes, commands, and exception display metadata before output. Commands remain escaped selectable markup referenced by stable IDs and never enter the script. The runner derives guard HTML from the exact canonical verdict artifact and stages both with JSON and screenshots under one owned project lock, rejecting symbolic-link/non-file output targets and restoring the prior coherent output set when publication fails. Generated HTML, verdicts, and screenshots remain sensitive local artifacts.
- Persistence canonicalizes the project root and revalidates real `.uiwitness` path boundaries before publication. The owned lock coordinates UIWitness runs; as with other local developer tools, it does not defend against a hostile same-user process mutating the project directory while a scan is actively publishing. Run scans only in a project directory controlled by the current user.
- `uiwitness open` validates the fixed `.uiwitness/report/index.html` target beneath the canonical invocation directory, rejects symbolic-link or non-regular path boundaries observed during validation, and passes the absolute path as one shell-free argument to an absolute system-launcher path so repository-local binaries cannot intercept the handoff. The operating-system handoff is pathname-based and cannot atomically pin the validated file, so the local project/report directory is trusted against concurrent same-user mutation during that handoff. The command does not generate, rewrite, upload, or parse report contents.
- Recommend ignoring both `.uiwitness/` and legacy `.statecraft/` evidence roots where reports may contain sensitive data. UIWitness never automatically reads, renames, copies, uploads, or deletes the legacy root.
- Screenshot privacy is fail-closed. Named selectors resolve only after readiness and before capture; exact matched nodes receive temporary random marker attributes plus non-clonable identity properties, and their identity/cardinality is checked again after capture before bytes are retained. Required absence, invalid syntax, exact-cardinality mismatch, DOM churn, or masked screenshot failure blocks the cell, discards bytes, and never falls back to an unmasked image. The mask fill is opaque `#0b0c0a`. `failures-only` discards passing bytes before staging; `none` performs no selector resolution or screenshot call. The schema-v1 evidence manifest contains only policy, counts, successfully captured mask IDs/cardinalities, and digests—never selectors, matched text, DOM content, marker tokens, or secret values.
- GitHub Actions evidence upload is an explicit repository-owner choice, not automatic UIWitness behavior. The documented workflow uses `if: always()` so failed scans remain diagnosable and uploads the complete `.uiwitness` bundle so report screenshots remain usable. Artifacts in a public repository must be treated as public; sensitive captures require a private repository with restricted read access or no upload. UIWitness's own release gate uploads only the deterministic fictional example evidence with short retention.
- The official Contract Guard Action is a thin adapter over the adopting repository's locked project-local CLI. It compares the CLI and Action release versions before browser work, never downloads a fallback package, passes bounded paths as shell-free argv values, and never evaluates pull-request metadata. Hosted output is escaped and bounded to a 512 KiB summary, 20 detailed findings, 10 default annotations, and 50 maximum annotations. The Action requests no pull-request write and examples grant only `contents: read`; fork pull requests remain secret-free. Never use `pull_request_target` or a secret-bearing `workflow_run` to execute untrusted contribution code. Evidence upload stays explicitly disabled by default, uses an immutable artifact-Action revision, and defaults to one-day retention when enabled.
- npm publication runs only from a non-prerelease GitHub Release workflow with read-only repository contents, job-scoped `id-token: write`, and a protected `npm-publish` Environment. The event commit, exact tag target, membership in `main`, package metadata, tarball contents, consumer installation, and registry integrity are checked before publication. All four packages use the `RujitRaval/uiwitness` trusted publisher for `release.yml` and `npm-publish`, with publishing access set to require 2FA and disallow bypass tokens. The one-time `v0.25.4` bootstrap completed on 2026-09-01; its temporary token and GitHub secret were removed within 17 minutes 5 seconds, and the cleanup-gated immutable-tag registry proof passed. Normal releases use short-lived OIDC credentials with no token configuration and start registry verification automatically. Never retain or recreate a bootstrap credential for normal releases, and never commit npm credentials, packed tarballs, cleanup evidence, or generated reports.
- The post-publication public URL gate installs only exact release packages from the explicit npmjs registry into a private temporary `npm init -y` project. It scans a repository-owned loopback fixture rather than a third-party site, validates that every screenshot remains inside the temporary artifact boundary, and removes the entire consumer after success or failure. It never reads npm credentials, production URLs, or user data.
- Persist screenshots, report JSON/HTML, verdicts, proposal families, optional JSON copies, and generation manifests with owner-only modes for new runner directories/files where supported. Reject symbolic links, unexpected hard links, paths over 1,024 characters, noncanonical/reserved paths, and changed immutable targets; publish no-clobber members with an atomic same-filesystem link. Stage and fsync the complete output set and its directory entries inside `.uiwitness/`, then serialize swaps with a process-owned phase-aware lock and durable bounded journal. Publish HTML last among report content and `.uiwitness/generation.json` last overall; the journal authenticates that exact marker and recovery verifies its referenced manifest before treating it as committed. Rollback hides the marker first and durably restores both sides of each rename. Auto-recover abandoned capture and journaled publication state, retain a durably committed generation when only cleanup was interrupted, and preserve ambiguous publishing/recovery data rather than risking the last good copies.
- Prefer mature dependencies and minimize runtime dependency count.
- `tldts` is pinned in core as the narrow MIT-licensed Public Suffix List implementation required to reject ICANN and private suffix cookie scopes. It performs no product-network access; its list is bundled in the package.
- The example application uses fictional, deterministic commerce data only. Its API fixtures must never contain copied customer records, credentials, tokens, or production endpoints; scenario interception stays local to the browser run. Customer fixture values live behind a Next.js `server-only` boundary, while client components import only the runtime contract. Production-browser regression coverage scans emitted static chunks to prevent restricted fixture fields from leaking into downloadable JavaScript.
